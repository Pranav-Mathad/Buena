# Keystone frontend

React client for the Keystone API: portfolio overview, per-property file
with sources, Ask panel, an inbox for signals and items awaiting review,
inbox search and reply drafting.

## Stack

React 18, TypeScript, Vite 5, React Router 6, TanStack Query 5, Tailwind CSS
3 with a small set of Radix UI primitives (`src/components/ui/`, generated by
shadcn/ui), Vitest and Testing Library.

## Scripts

| Command              | What it does                                    |
| -------------------- | ----------------------------------------------- |
| `npm ci`             | Install exact versions from `package-lock.json` |
| `npm run dev`        | Dev server on <http://localhost:8080>           |
| `npm run build`      | Production build into `dist/`                   |
| `npm run preview`    | Serve the production build                      |
| `npm run lint`       | ESLint, failing on any warning                  |
| `npm run typecheck`  | `tsc --noEmit` for the app and the Vite config  |
| `npm test`           | Vitest, single run                              |
| `npm run test:watch` | Vitest in watch mode                            |

## Environment

| Variable            | Purpose                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `VITE_API_BASE_URL` | Base URL of the Keystone API, for example `http://localhost:8000`                                   |
| `VITE_REPO_URL`     | Optional. Source repository; the header and footer link to it when set                              |
| `VITE_PUBLIC_URL`   | Optional. Public URL of this frontend; when set, the build adds absolute `og:image` / `og:url` tags |

Copy `.env.example` to `.env.local`. Env files other than the example are
gitignored. The backend must list the frontend's origin in
`KEYSTONE_CORS_ORIGINS`; its default already includes
`http://localhost:8080`.

## Testing

`npm test` runs Vitest in jsdom with Testing Library. Tests sit next to the
code (`src/lib/*.test.ts`, `src/**/__tests__/*.test.tsx`) and cover the API
client's DTO mapping and error types, the markdown helpers, the Ask panel's
three answer states, the property page's section rendering, live
notifications from the server-sent event stream, and approving a signal from
the inbox. `src/test/utils.tsx` provides `renderWithProviders` and a
`mockFetch` that routes requests by method and path; `src/test/setup.ts`
replaces `EventSource` with a controllable mock. There are no snapshot tests.

Before pushing: `npm run lint && npm run typecheck && npm test && npm run build`.
