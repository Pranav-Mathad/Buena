# Keystone frontend — audit 2026-04-25

Audit-only run. No files modified. Demo is 2026-04-26 (tomorrow), 2 minutes.

## Repo overview

- **Framework**: Vite 5 + React 18 + TypeScript, `@vitejs/plugin-react-swc`. Module type `module`. Project name in package.json is still the Lovable scaffold default `vite_react_shadcn_ts`.
- **Routing**: `react-router-dom` v6, `BrowserRouter` mounted in [src/App.tsx](src/App.tsx). Four real routes plus a catch-all `NotFound`.
- **State**: `@tanstack/react-query` is installed and a `QueryClientProvider` is mounted in [src/App.tsx:14-17](src/App.tsx#L14-L17), but no queries exist yet — local component state only. Theme state lives in a custom Context at [src/components/ThemeProvider.tsx](src/components/ThemeProvider.tsx).
- **Styling**: TailwindCSS 3 + `tailwindcss-animate` + `@tailwindcss/typography`. Single global stylesheet at [src/index.css](src/index.css) defines HSL CSS variables for both themes plus a couple of custom component classes (`.pill`, `.swatch`, `.dot`, `.display`).
- **Component library**: shadcn/ui (full kit installed under [src/components/ui/](src/components/ui/) — 50 components, all Radix-based) plus a small project-specific layer at [src/components/ui-bits.tsx](src/components/ui-bits.tsx) (`Card`, `StatusPill`, `Swatch`, `PrimaryButton`, `SecondaryButton`). `lucide-react` for icons.
- **Theming**: custom ThemeProvider — toggles `class="dark"` on `<html>`, persists to `localStorage["keystone-theme"]`, falls back to `prefers-color-scheme`. `next-themes` is installed as a dependency but is **not used**.
- **Tests**: Vitest 3 + jsdom + `@testing-library/react`. Setup at [src/test/setup.ts](src/test/setup.ts), one trivial example at [src/test/example.test.ts](src/test/example.test.ts) that asserts `true === true`. No real component tests.
- **Build setup**: dev server runs on port `8080`, host `::` (see [vite.config.ts:8-13](vite.config.ts#L8-L13)). HMR overlay is disabled. `lovable-tagger` is loaded only in dev mode.
- **Lockfiles**: both `bun.lockb` and `package-lock.json` are present, suggesting the project was bootstrapped with bun by Lovable but has been touched by npm since. Pick one before demo to avoid drift.
- **Run dev server**: `npm run dev` (or `bun dev`) → http://localhost:8080.

## Code smells

- **`console.error` left in NotFound** — [src/pages/NotFound.tsx:8](src/pages/NotFound.tsx#L8). Harmless for the demo (no one will hit a 404) but should go.
- **`useMemo` used as side effect** — [src/components/AskPanel.tsx:48-53](src/components/AskPanel.tsx#L48-L53). `useMemo` is called for its `setInput`/`setSubmitted` calls, not its return. Use `useEffect`. Functionally works in current React but is a footgun and may emit warnings under React strict mode.
- **Hardcoded API_BASE_URL** — [src/lib/data.ts:1](src/lib/data.ts#L1) defines `export const API_BASE_URL = "https://api.keystone.demo"`. Constant is unused (no fetch calls anywhere) and ignores the `VITE_API_BASE_URL` env contract. Will mislead Phase 12 wire-up.
- **Hardcoded UUID in nav** — [src/components/Layout.tsx:7](src/components/Layout.tsx#L7) bakes the WE 29 UUID into the "Properties" link. Won't generalize.
- **Property detail ignores `:id`** — [src/pages/PropertyDetail.tsx:77-79](src/pages/PropertyDetail.tsx#L77-L79). Any property card click loads identical body content. A judge who clicks a non-hero property (Berliner Straße, Müllerstraße) will see WE 29's water damage in the file and the contradiction is glaring.
- **Two toast surfaces mounted simultaneously** — [src/App.tsx:20-21](src/App.tsx#L20-L21) renders both `<Toaster />` (shadcn/Radix) and `<Sonner />`. Neither is currently triggered. Pick one.
- **Unused files**: [src/App.css](src/App.css) (Vite scaffold logo CSS), [src/pages/Index.tsx](src/pages/Index.tsx) (re-exports Portfolio but no route uses it), [src/components/NavLink.tsx](src/components/NavLink.tsx) (forwardRef wrapper, never imported), [src/hooks/use-mobile.tsx](src/hooks/use-mobile.tsx) (no consumers).
- **Unused dependency**: `next-themes` is in package.json but the live theme implementation is the custom Context. Either remove the dep or migrate to it.
- **TypeScript strictness disabled** — [tsconfig.app.json:19-23](tsconfig.app.json#L19-L23) disables `strict`, `strictNullChecks`, `noImplicitAny`, `noUnusedLocals`, `noUnusedParameters`. Fine for hackathon velocity, worth flagging.
- **Briefing modal markdown parser is brittle** — [src/pages/PropertyDetail.tsx:53-65](src/pages/PropertyDetail.tsx#L53-L65) splits on `**` and joins on `""`, which strips all asterisks. Works for the current `briefingMarkdown` shape but will break on any italic/inline-bold the backend might emit later.
- **Two divergent "source" shapes** — Property file `Fact.source` is a plain string ([src/lib/data.ts:49-55](src/lib/data.ts#L49-L55)); Q&A `sources` items have `{id, channel, date, snippet}` ([src/lib/data.ts:135](src/lib/data.ts#L135)). When the backend wire-up lands you'll need to reconcile these or the renderer split will get worse.
- **Components over 400 lines**: none. Largest are [data.ts:343](src/lib/data.ts) (fixtures, fine), [DraftReply.tsx:187](src/pages/DraftReply.tsx), [AskPanel.tsx:184](src/components/AskPanel.tsx), [PropertyDetail.tsx:165](src/pages/PropertyDetail.tsx). All readable.
- **No inline `style={{}}` anywhere** — clean. Tailwind tokens and `cn()` are used consistently.
- **Two lockfiles** — `bun.lockb` + `package-lock.json` both committed. Decide.
- **README is still "TODO"** — [README.md](README.md). Cosmetic.
- **The `live · Buena` indicator** — [src/components/Layout.tsx:38-41](src/components/Layout.tsx#L38-L41) is pure decoration with a pulsing green dot. Fine, but if a judge asks "what's that connected to?" the honest answer is "nothing." Worth knowing.
- **Inbox in Compare doesn't react to question** — [src/pages/Compare.tsx:53-67](src/pages/Compare.tsx#L53-L67) renders the same 14 emails regardless of which `compareQuestions` option is selected. The whole point of the side-by-side is to show that the inbox can't answer the bank-account or Verlängerung question at all; right now the left column is identical for every selection.

## Open questions

1. **Source-link target** — when a `[source]` link is clicked, should it open (a) the original document/email URL hosted by the backend, (b) an in-product modal with the raw event content, or (c) just the snippet inline? Backend exposes events with snippets but I don't see a per-event detail endpoint in the listed contract. Need a call before wiring this for real.
2. **Per-property file beyond the hero** — does the demo ever click off WE 29? If yes, do we need real data for Berliner/Müllerstraße or is "ingesting…" empty-state acceptable?
3. **Compare left column behavior across questions** — should the inbox visibly *fail* differently for each of the four questions (e.g., "0 results matching 'bank account'"), or stay generic and let the right column do the work? Tied to recommendation 2.
4. **`next-themes` retention** — keep installed for some future plan, or remove and lock in the custom ThemeProvider?
5. **`live · Buena` indicator** — decoration only, or wire it to a real backend health check (`GET /properties` HEAD)?
6. **Lockfile** — bun or npm? Both lockfiles are committed; demo machine should standardize on one.
7. **Tone consistency** — chrome copy is exclamation-free per brand, but tenant fixtures (`Eingangstür kaputt!`, `Wasserschaden Küche — dringend`) use exclamations. Read as deliberate (tenant voice ≠ chrome voice), but worth confirming for any new fixtures.
8. **TypeScript strictness** — leave loose for hackathon velocity, or tighten before Phase 12 wire-up so the API client gets typed properly?
